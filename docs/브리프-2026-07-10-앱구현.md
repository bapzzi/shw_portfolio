> 교차세션 통제 루프. 실행 세션은 **결정하지 않고 절차만** 수행하고 회신한다.
> 통제 세션(erp-club 포폴 트랙)이 회신을 session-review로 검증해 승인/반려.
> 작성 2026-07-10.

## ① 목표

`career/portfolio`에 React 앱(`app/`)을 구현·배포해, content/ 원고 4건이 다크+옐로 타임라인 디자인으로 렌더링되는 라이브 포트폴리오를 만든다.

## ② 사전 결정 (고민 금지)

**단일원천 문서 3개 — 실행 전 반드시 읽는다. 어긋나면 브리프가 아니라 이 문서들이 원천:**
- 디자인: `~/claude/erp-club/docs/specs/2026-07-10-design-rules.md` (팔레트 토큰·폰트·텍스트 밀도 §0·시그니처 §4·금지목록 §5)
- IA·콘텐츠 원칙: `~/claude/erp-club/docs/specs/2026-07-10-portfolio-mainpage-design.md` §2
- 원고: 이 repo `content/*.md` 4건 (케이스 3 + journey)

**결정 사항 (선택지 없음):**
- 스택: **Vite + React + TypeScript**, 그릇형 — 앱 알맹이는 `app/`, 루트는 한글 표면(README·작업기록·content·docs)
- 라우팅: react-router. 라우트 = `/`(홈) · `/case/adsp-board` · `/case/ai-relay` · `/case/portfolio` · `/how`(작업 방식). v2 챗봇은 만들지 않는다
- 콘텐츠: **content/ md가 유일 원천 — 앱 코드에 문안 하드코딩 금지**(빌드 시 import·파싱). 원고 문안 수정 금지 — 오탈자 발견 시 고치지 말고 회신 목록에
- 원고의 노드 구조가 곧 타임라인 컴포넌트 명세: `버전/시기 칩 → 문제 한 줄 → AI활용 칩들 → 결정 한 줄 + ⊘기각 곁가지(스탬프 #E0604C) → 결과 수치`. 프롬프트 펼침은 터미널 창 오브젝트(신호등 도트+파일명 바), 케이스당 1곳
- 폰트 로드(CDN, 디자인규칙 §2의 URL 그대로): Paperlogy(800·900) / Pretendard Variable / JetBrains Mono+D2Coding
- **금지 재확인**: 크림/아이보리 톤, 고스트 워터마크, 장식 blob, 얼굴 사진, 스킬 바, 액센트 2색, 섹션당 문장 3개 이상(텍스트 밀도 §0), "LG CNS 합격" 표현(→"선발")
- **공개 경계(journey.md 표기 규칙)**: 생년월일·주소·전화 절대 미노출. About=학력·SAP 자격증 2종 중심·수상 2. Contact=이메일 1개(`win737449@gmail.com`)
- 옛 정적 페이지 **삭제 승인됨**(spec §2 확정): index/about/portfolio/contact/lotte-erp/university.html + style.css + script.js. 단 **삭제 전 태그 확인** — `git tag`에 v1 계열 태그(v1-internet-course)가 없으면 삭제 직전 HEAD에 `git tag -a v1-internet-course -m "정적 페이지 시절 보존점"` 생성 후 진행
- git: main 직접 커밋(독립 repo·단독 작업), 논리 단위로 작게. push는 마일스톤마다. `git add`는 경로 지정(`-A` 금지)
- Vercel: 실행 세션은 `vercel.json`(SPA rewrites) 준비 + 빌드 검증까지. **프로젝트 생성·repo 연결은 사용자가 대시보드에서 실행**(계정 권한) — 안내문만 준비. 루트 디렉토리 설정=`app`
- dev 서버는 검증 후 반드시 종료(다른 세션 잠금 방지)

## ③ 절차

1. `git -C ~/claude/career/portfolio pull` → 워킹트리 클린 확인(`git status`)
2. 위 단일원천 문서 3개 + content/ 4건 정독
3. 태그 확인 → 옛 정적 파일 삭제 → `chore: 정적 페이지 은퇴(v1 태그 보존)` 커밋
4. `app/` 스캐폴드(Vite react-ts) → 디자인 토큰 CSS(:root 변수, 디자인규칙 §1 값 그대로) + 폰트 → `npm run build` 통과 확인 → 커밋
5. content 파서 + 타임라인 컴포넌트 → 케이스 상세 3페이지 → 커밋(페이지 단위)
6. 홈(히어로→실물 3카드→여정 타임라인→About→Contact) → `/how` → 커밋
7. 검증: `npm run build` + 미리보기 서버에서 **3뷰포트 캡처**(폰 390·맥 1280·데스크톱 1920, `docs/shots/v2/`에 저장) + 내부 라우트·외부 라이브 링크(erpstudy.vercel.app, ai-relay-sigma-two.vercel.app, kwu-erpclub.github.io) 전수 클릭 확인 → dev 서버 종료
8. push → Vercel 연결 안내문 작성 → 회신서 작성

## ④ 위험·롤백

- 정적 페이지 삭제 실수 → `git revert <삭제 커밋>` 또는 태그로 복원(`git checkout v1-internet-course -- <파일>`). 이력·태그가 보존되므로 파괴적이지 않음
- 빌드 실패 상태로 push → push 전 `npm run build` 필수. 이미 push했으면 수정 커밋(force push 금지)
- content 파싱이 원고 형식과 안 맞음 → **원고를 고치지 말고** 파서를 원고에 맞출 것. 구조적으로 불가하면 중단 후 회신
- Vercel 배포는 사용자 게이트라 실행 세션에서 라이브 사고 없음

## ⑤ 회신 계약

1. 커밋 해시 목록(한 줄 요약 포함) + push 여부
2. 3뷰포트 캡처 파일 경로(최소 홈·케이스 1·/how × 3폭)
3. 빌드 결과(경고 포함)·lint 결과
4. 링크 전수 확인 표(내부 라우트 + 외부 3 URL, OK/FAIL)
5. 오탈자·원고 이슈 목록(수정하지 않았음을 명시)
6. case-portfolio.md에 채울 실측 수치 후보(이 구현의 커밋 수 등) — **원고에 직접 쓰지 말고 회신만**
7. Vercel 연결 안내문(사용자가 따라 할 단계)
8. 브리프에서 벗어난 판단이 있었다면 전부 명시
