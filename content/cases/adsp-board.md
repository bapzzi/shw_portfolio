## 타임라인

### ◆ MVP → 라이브 (6월 말)
- **문제**: 주 1회 오프라인·예습 기반 스터디, 각자 어디까지 했는지 아무도 모름
- **AI활용**: `MVP 구축` `opus 최종 리뷰 — Critical 0건 판정 후 머지`
- **결과**: erpstudy.vercel.app 라이브 → 독립 repo 분리(Tier1). 가입 없이 이름+PIN 입장 — 8명에게 가입 절차를 요구하면 그 자체가 이탈 지점

### ◆ 절(節) 기반 재설계 (7/1 · 커밋 61)
- **문제**: "어느 절이 약한지"를 못 봄 + 임의 20일 배분이 기출 암기형 시험과 불일치
- **AI활용**: `스펙 설계` `직접 요약한 내용을 병렬 가공 → 콘텐츠 제작` `전수 검증(JSON·정답인덱스·경계·렌더)`
- **결정**: 진도 원자 단위 = 절(과목3→장8→절29), 25 공부일 재배분 + 페이지 앵커
- **⊘기각**: Day 단위 구 스펙 — 문서에 "이 스펙은 …을 대체한다" 명시 폐기
- **결과**: 절 기반 구조로 진도·퀴즈·성취도 전면 재배선

### ◆ v2.0.0 — 지표체계 개편 (7/2 · 커밋 74)
- **문제**: "진도 0%인데 준비도 73%" — 지표 이름이 화면마다 다른 세계
- **AI활용**: `실계정 재현으로 근본원인 확정 — 추측으로 고치지 않는다` `지표 사전 통일` `TDD(완료 로직 중앙화)`
- **결정**: 완료 = 정리본 체크 AND 퀴즈 100%. 준비도 공식은 **사용자가 직접 수정**(19.8→1.2 체감 일치)
- **⊘기각**: 공들여 만든 수동 기출입력 기능 — 2주 만에 자체 드롭(마이그 0014, 데이터 원천 일관성 우선)
- **결과**: 테스트 67→132

### ◆ 감독 체계 구축 (7/5)
- **문제**: "뭐가 효율적인지 판단 근거가 안 남는다"
- **AI활용**: `분석·제안=AI / 결정·소통=사람 — 역할 경계를 스펙에 명문화` `읽기전용 집계 스크립트(해석 없음)`
- **결정**: 주간 감독 리포트, 자동 스케줄 없음(매주 사람이 트리거 — 통제>자동화)
- **⊘보류**: 공지 활용 제안 — 사용자 판단 "카톡 중심 유지"
- **결과**: 첫 주 기준선 "활성 1/8명(운영자 본인뿐)" 발견 → 로그인 로그 즉시 채택·배포(마이그 0018)

### ◆ v2.3.0 — 진행도 일차 기반 전환 (7/7)
- **문제**: 지표 17% ↔ 사용자 체감 8% (2일차, 계획대로 했는데)
- **AI활용**: `산술 검증 54/316=17.1%` `판정 3안 분기 → 사용자 결정` `서브에이전트 리뷰 → Critical 2건 수정`
- **결정**: 절학습=자동 / 점검·복습=수동 체크 / 모의·기출=응시 자동
- **⊘기각**: 문항 커버리지 표시(내부 재료로 강등) · 달력 선형 보간("선형 보간 은퇴" 커밋)
- **결과**: 테스트 159 GREEN · 마이그 0019 · 배포

### ◆ 문항 표시 개편 — 라이브 데이터 위에서 고치기 (7/26)
- **문제**: "실제 문제와 다르게 보인다" — R 콘솔 출력·거래표가 공백 뭉개짐으로 무너지고, 그림 0장·계산 유형 부재
- **제약**: 팀원 답안 2,425건이 이미 쌓여 있고 문항 테이블 외래키에 삭제 규칙이 없어 기존 시드 방식(삭제 후 재삽입)은 실패하는 상황
- **결정**: 개정판 두 벌 운영 초안을 **폐기** — 내용이 아니라 표기만 바꾸므로 **같은 행 제자리 UPDATE**. "선택지 순서·정답 인덱스 불변"을 하드룰로 두고 위반 시 스크립트가 중단
- **AI활용**: `지문 렌더러 신설(고정폭·공백 보존)` `재포맷 50문항 + 신규 42문항 + 도해 SVG 11장` `개편 전후 전수 대조`
- **결과**: 877문항 정답·선택지 변경 0건 확인·답안 손실 0. 이어서 실전 90분 타이머(만료 시 잠금·자동 채점) — 실제 시험이 50문항 90분이므로

### ◆ 시험주간 — 버리는 국면의 도구 (7/30 · D-9)
- **문제**: 전 범위 완성 후 9일 — "전부"는 전략이 아닌데 보드는 모든 절을 균등하게 보여줌
- **AI활용**: `실전 300문항 절별 전수 분류 → 배지 근거` `핵심 4절 실전형 48문항 — 형태 배분도 실측 비율(매칭 43%·함정 25%)대로`
- **결정**: 29절에 3단계 중요도 배지(★핵심 12·낮음 4 — "출제 0~1문항, 건너뛰어도 된다" 명시). DB 무변경·파일 한 장으로 구현해 시험 후 원복 가능하게
- **결과**: 186테스트 GREEN·INSERT-only 48건 적용(UPDATE·DELETE 0)

### ◆ 1기 종결 — 읽기전용 아카이브로 닫기 (8/8~8/10)
- **문제**: 2기가 시작되면 1기 데이터가 덮인다
- **결정**: 시험 당일 DB를 그대로 떠서 보드 밖에 고정(멤버별·일자별·응시 1,427건·문항별 정답률 1,006건 + 재현 쿼리) → 8/10 보드 쓰기 전면 차단·계정도 마스터 하나만
- **결과(실측)**: 누적 답안 9,118건·응시 1,427회. 문항별 정답률로 **결함 의심 61문항·무변별 108문항을 문항 단위로 지목** — 2기 개편의 근거가 도구 안에 남음
- **⊘보류**: 실제 시험 성적과의 대조 — 합격 발표(8/28) 후 자기보고 수집해 보드 활동량이 점수를 얼마나 맞혔는지 확인(맞으면 2기 예측 지표로 승격)

## 프롬프트 펼침 (대표 1곳 — v2.3.0 노드)
> **설계 지시(원문 기반 재구성)**: "진도 판정은 절 학습만 자동으로 하고, 점검·복습은 수동 체크로 분리. 사용자가 통제감을 잃지 않는 게 자동화보다 우선." — 출처: 2026-07-07 spec 사용자 확정 결정 표

## 배운 것 한 줄
지표는 계산이 맞아도 사용자의 멘탈모델과 다르면 틀린 것이다 — 고칠 대상은 숫자가 아니라 기준이었다. 그리고 그 지표조차 절 퀴즈 74% vs 실전 첫 시도 62.5%처럼 무엇을 재는지에 따라 갈린다 — 실력 판단엔 첫 시도만 남겼다.
